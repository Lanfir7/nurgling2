# Заметки об обновлениях для игроков

Игрок видит кнопку «Что нового» с ненавязчивым индикатором. Окно не открывается
само. В начале — короткая строка для каждого изменения выпуска, затем полные
подробности по желанию и переход к предыдущим выпускам. В клиенте хранится до 30 выпусков, без запросов
к серверу. Прочитанная новость запоминается на этой установке клиента.

## Во время разработки

Вместе с готовым изменением добавляйте `changes/YYYY-MM-DD-short-name.json`.
Образец — `changes/2026-09-13-release-feed.json`.

- `id`: уникальный постоянный идентификатор; после публикации не переиспользовать.
- `priority`: 0–10; задаёт порядок заметок в кратком содержании и подробностях.
- `summary.ru` / `summary.en`: одна фраза до 180 символов о пользе для игрока.
- `detail.ru` / `detail.en`: один абзац до 500 символов: что изменилось и где найти.

Пишите о фактическом результате: «Карта запоминает масштаб», а не
«Исправлена сериализация». Без классов, коммитов, внутренних задач и обещаний.
Объединяйте мелкие связанные исправления в одну заметку. Чисто внутренние
рефакторинги не требуют новости. Для незавершённых возможностей заметку пока
не добавляйте. Старые заметки сохраняйте: история их идентификаторов защищает
от повторной публикации. Исправления опубликованного поведения — новая заметка.

Проверка: `python tools/release_notes.py --check`.
Тесты сборщика: `python -m unittest discover -s tools -p test_release_notes.py`.

## При релизе

`ant release` до сборки JAR собирает ещё не опубликованные заметки, присваивает
точную версию из `build.xml` и `build.num`, дату UTC, добавляет предыдущие выпуски.
Python 3 нужен только при подготовке релиза, игроку он не нужен.
Другой интерпретатор: `ant -Drelease.notes.python=/path/to/python release`.

История берётся из `release/release-notes.json`; CI забирает её из предыдущего
latest и передаёт через `-Drelease.notes.previous=build/previous-release-notes.json`.
Для самого первого релиза отсутствие истории допустимо. Для последующих
ручных релизов обязательно используйте файл последнего опубликованного выпуска.
Повреждённая история останавливает сборку. Выпуск без новых заметок не создаёт
повторного уведомления. История и список использованных ID сохраняются в
`release/release-notes.json`, а внутри JAR — `/nurgling/news/releases.json`.
Перенос latest в stable сохраняет тот же файл и те же идентификаторы.

Обычные `ant jar` и `ant run` всегда включают сохранённую историю из
`src/nurgling/news/releases.json`. Подготовка выпуска обновляет этот снимок;
он хранится с исходниками и переживает очистку каталога сборки. Новые файлы
из `changes/` добавляются только при подготовке выпуска. Просмотр снимает
индикатор непрочитанного, но никогда не удаляет историю.
Для локальной проверки упаковки без публикации и изменения номера сборки:
`ant prepare-release-notes jar`. Результат — `build/hafen.jar`.
Это лишь локальная сборка; публикация выполняется отдельно.

Для обычного запуска достаточно `ant run`. Команда `ant run-with-news`
дополнительно подготавливает ещё не включённые заметки перед запуском.
Кнопка «i» с подсказкой «Что нового» находится после входа персонажем справа
в первом ряду главного меню, над кнопкой энциклопедии. На экране входа её пока нет.
Если файла предыдущего выпуска нет, подготовка использует сохранённый снимок.
