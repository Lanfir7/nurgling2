## Система сессий/профилей (будущая реализация)

### Архитектура

#### Вариант 1: Множественные UI в одном окне
```
MainFrame
  └── TabbedPane или Panel с вкладками
       ├── Session 1 (NGameUI + Session)
       ├── Session 2 (NGameUI + Session)
       └── Session 3 (NGameUI + Session)
```

**Плюсы:**
- Проще реализовать
- Меньше изменений в существующем коде
- Каждая сессия независима

**Минусы:**
- Каждая сессия создает свой UI, что потребляет много памяти
- Рендеринг всех сессий одновременно может быть тяжелым

#### Вариант 2: Единый UI с переключением сессий
```
MainFrame
  └── SessionManager
       ├── Active Session (NGameUI)
       └── Background Sessions (Session only, без UI)
```

**Плюсы:**
- Меньше потребление памяти (один UI)
- Можно рендерить только активную сессию
- Фоновые сессии работают в headless режиме

**Минусы:**
- Сложнее реализовать
- Нужно сохранять/восстанавливать состояние UI при переключении

#### Вариант 3: Гибридный подход (рекомендуемый)
```
MainFrame
  └── SessionManager
       ├── Active Session (полный UI + рендеринг)
       ├── Visible Sessions (мини-UI, без рендеринга)
       └── Background Sessions (headless, только логика)
```

**Плюсы:**
- Баланс между функциональностью и производительностью
- Можно видеть статус нескольких сессий одновременно
- Фоновые сессии не потребляют GPU

**Минусы:**
- Наиболее сложная реализация

### Компоненты для реализации

1. **SessionManager**
   - Управление списком сессий
   - Переключение между сессиями
   - Сохранение/восстановление состояния

2. **Session**
   - Обертка над Session из haven
   - Хранение состояния (UI, контекст, настройки)
   - Методы для приостановки/возобновления

3. **SessionSwitcher Widget**
   - UI для переключения между сессиями
   - Отображение статуса каждой сессии
   - Быстрое переключение (горячие клавиши)

4. **SessionStorage**
   - Сохранение состояния сессий при переключении
   - Восстановление при перезапуске клиента

### Сложность реализации

**Оценка:** Средняя-Высокая

**Основные задачи:**
1. Рефакторинг NGameUI для поддержки множественных сессий (2-3 недели)
2. Создание SessionManager (1-2 недели)
3. UI для переключения сессий (1 неделя)
4. Тестирование и отладка (1-2 недели)

**Итого:** ~5-8 недель разработки

### Пример кода структуры

```java
public class SessionManager {
    private List<GameSession> sessions = new ArrayList<>();
    private GameSession activeSession;
    
    public void addSession(String accountName, String password) {
        GameSession session = new GameSession(accountName);
        sessions.add(session);
        if (activeSession == null) {
            switchToSession(session);
        }
    }
    
    public void switchToSession(GameSession session) {
        if (activeSession != null) {
            activeSession.pause();
        }
        activeSession = session;
        activeSession.resume();
        updateUI();
    }
}
```
